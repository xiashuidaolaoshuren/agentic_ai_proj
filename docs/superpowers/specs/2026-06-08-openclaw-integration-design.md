# Milestone 3 OpenClaw Integration Design

Date: 2026-06-08

## Summary

Milestone 3 integrates the existing AI News Research Agent with OpenClaw as an outer gateway.
The chosen implementation is a local OpenClaw skill that triggers the existing Python CLI digest
flow using natural-language prompts. OpenClaw remains the channel gateway and session layer; this
project remains the retrieval, ranking, summarization, and persistence engine.

This milestone intentionally prioritizes reliability and local operability over a broader service
surface. A future HTTP adapter can be added later without changing the digest core.

## Scope

### In Scope

- Add a local OpenClaw skill for natural-language AI digest requests.
- Reuse the existing CLI entrypoint in `src/ai_news_agent/cli.py`.
- Preserve shared source selection through `DigestRequest.connector_names` via
  `src/ai_news_agent/sources.py`.
- Add a thin OpenClaw-facing Python adapter boundary at `src/ai_news_agent/adapters/openclaw.py`
  for safe argument shaping and testability.
- Provide setup and usage docs for local OpenClaw Gateway integration.
- Add deterministic tests for adapter argument normalization and CLI integration behavior.

### Out of Scope

- Gateway-native OpenClaw plugin/tool implementation in TypeScript.
- Production hosting/deployment architecture.
- New source connectors (arXiv, Hugging Face, RSS).
- Scheduled digest execution.
- Follow-up Q&A orchestration inside OpenClaw for this milestone.
- A required HTTP `POST /digest` server for Milestone 3.

## Architecture

OpenClaw is the external assistant interface. The AI News Research Agent remains an independent
Python subsystem.

```text
OpenClaw channel message
  -> OpenClaw Gateway
  -> workspace skill (ai-news-digest)
  -> OpenClaw exec tool
  -> uv run ai-news-agent digest ...
  -> existing LangGraph workflow
  -> markdown digest reply
  -> OpenClaw channel response
```

### Core Boundary Rules

- Do not couple digest workflow internals to OpenClaw-specific runtime semantics.
- Keep the CLI path as the first stable contract for Milestone 3.
- Keep OpenClaw integration logic thin and adapter-oriented.
- Preserve current storage, ranking, and summarization behavior.

## User Experience

Primary interaction remains natural language in OpenClaw-connected channels:

- "Give me today's AI digest."
- "Give me today's AI digest from GitHub only."
- "Give me this week's AI digest on RAG and agents."

The skill should map prompt intent into a constrained CLI argument set:

- `timeframe`: default `today`; support common simple values.
- `sources`: default `github,bilibili`; support source toggles.
- `topics`: optional extraction; fallback to existing defaults.

Output is the existing markdown digest generated by the Python app. Source links and caveats must
be preserved in the final OpenClaw response.

## Components

### `src/ai_news_agent/adapters/openclaw.py`

Responsibilities:

- Normalize source/timeframe/topic hints into validated options.
- Build a safe CLI argument list (no shell interpolation).
- Expose helper functions that can be tested without OpenClaw running.

Non-responsibilities:

- No direct connector logic.
- No direct modifications to ranking/summarization semantics.
- No runtime control of OpenClaw Gateway.

### `openclaw/skills/ai-news-digest/SKILL.md`

Responsibilities:

- Describe natural-language triggers for digest use cases.
- Instruct OpenClaw to invoke the project CLI through `exec`.
- Document how to pass constrained options (`timeframe`, `sources`, `topics`).
- Keep instructions concise and deterministic.

Recommended gating metadata:

- Required binary check (`uv`).
- Optional environment requirements for live runs (`OPENAI_API_KEY`).

### Existing Reused Boundaries

- `src/ai_news_agent/cli.py` for process-level invocation.
- `src/ai_news_agent/request.py` and `src/ai_news_agent/sources.py` for source mapping.
- `src/ai_news_agent/graph/workflow.py` for digest orchestration.
- Existing storage and logging layers.

## Error Handling

User-facing errors returned through OpenClaw should be concise and actionable:

- Missing API key in live mode.
- Invalid source selection.
- Empty digest results.
- Connector warnings (for example Bilibili anti-bot constraints).

Detailed diagnostics remain in application logs.

## Security

Milestone 3 assumes local-first trusted operation:

- OpenClaw Gateway should remain loopback/local for this integration.
- Skill command execution should use fixed command templates and validated args.
- Avoid dynamic shell string assembly.
- Keep `exec` access restricted to trusted local agent/workspace contexts.

## Testing Strategy

Automated:

- Adapter unit tests for option parsing and safe argv generation.
- CLI regression tests using fake mode for deterministic output paths.
- Error-path tests for invalid arguments and missing live configuration.

Manual:

- Local OpenClaw smoke checklist:
  - Install/enable skill.
  - Trigger digest through natural language.
  - Verify source selection behavior.
  - Verify output includes source links and caveats.

## OpenClaw Assumptions Used For This Design

This design uses two reference classes gathered during brainstorming:

1. Local tutorial reference:
   - `docs/openclaw.pdf` in this repository.
2. Official OpenClaw docs snapshots consulted during design:
   - OpenClaw overview (`docs.openclaw.ai`).
   - Gateway operations and local runtime guidance (`documentation.openclaw.ai/gateway`).
   - Skills model and SKILL.md behavior (`docs2.openclaw.ai/tools/skills`).

Assumptions derived from those references:

- OpenClaw is gateway-first and channel-oriented.
- Skills are markdown-driven instruction units suitable for tool/command delegation.
- Local loopback and explicit auth controls are core operational defaults.

If upstream OpenClaw docs materially change before implementation, update this spec before coding.

## Milestone 3 Acceptance Criteria

- A local OpenClaw skill can trigger digest generation through natural-language prompts.
- The skill executes the existing Python digest flow via CLI without altering digest core behavior.
- Source selection still maps through `DigestRequest.connector_names`.
- Output quality and caveat behavior are consistent with current CLI/Gradio digest behavior.
- Basic automated tests and one manual local OpenClaw smoke path are documented and passing.
